# Результат 5. Оптимізація «до/після»: top_k 5 → 3

**Гіпотеза.** Найрелевантніші фрагменти після reranker стоять першими, тому скорочення контексту з 5 до 3 фрагментів зменшить токени
й затримку без суттєвої втрати якості. **Змінений фактор** — лише `top_k`; модель, промпт, пошук, вікно 150 слів, seed, 39 тестів і суддя однакові.

Прогони: `python scripts/run_eval.py --name baseline` і `--name topk3 --set top_k=3`; порівняння `scripts/compare_runs.py`
(`rag_optimization_table.md`); токени й затримка — `scripts/measure_cost.py` (`cost_latency_table.md`).

## Якість

| Метрика | top_k = 5 | top_k = 3 | Δ |
|---|---|---|---|
| Правильність (answerable) | 0,700 | 0,700 | 0 |
| Context recall (вікно) | 0,680 | 0,583 | −0,097 |
| Faithfulness (суддя) | 1,000 | 0,948 | −0,052 |
| Citation accuracy (суддя) | 0,909 | 0,861 | −0,048 |
| Правильні «не знаю» | 1,000 | 1,000 | 0 |
| Хибні «не знаю» | 0,150 | 0,150 | 0 |
| Конфлікт: обидві версії | 0,000 | 0,000 | 0 |
| Захист від injection (без фільтра / з фільтром leak) | 0,75 / 1,00 | 0,25 / 0,75 | −0,50 / −0,25 |

## Затримка, токени, вартість

Затримки самих прогонів не порівнюються (різний час, паузи до 64 хв у baseline), а `prompt_eval_count` Ollama зменшується кешуванням
префікса. Тому токени пораховано токенізатором Qwen2.5 на відтворених промптах, а затримку — окремим контрольованим виміром:
10 тестів, обидві конфігурації поспіль із чергуванням порядку, без судді.

| Показник | top_k = 5 | top_k = 3 | Δ |
|---|---|---|---|
| Токени промпту, середнє (медіана) | 5306 (4892) | 3763 (3536) | −29 % |
| Повний запит p50 / p95, с | 95,8 / 157,9 | 48,3 / 102,3 | −50 % / −35 % |
| Парне відношення часу (медіана) | — | 0,666 | −33 % |
| Токени відповіді (сер.) | 74,6 | 86,8 | +16 % |
| Вартість генерації (локально) | 0 $ | 0 $ | 0 |
| Вартість судді за прогін | 0,0101 $ | 0,0091 $ | −10 % |
| Умовна вартість хмарної генерації (gpt-oss-120b у Groq), $/запит | 0,00083 | 0,00060 | −28 % |

## Висновок

Гіпотезу підтверджено лише частково: вартість знизилась (−29 % токенів, −50 % медіанної затримки), правильність за ключовими фактами
та сама (0,70), але погіршились context recall (−0,097), faithfulness (−0,052), citation accuracy (−0,048) і стійкість до injection
(0,75 → 0,25; з фільтром 1,00 → 0,75). Для локального генератора вартість — лише час, а для бази знань диспетчерів повнота й безпека
важливіші, тому зміна не окупається: залишено **top_k = 5** з вихідним фільтром leak. Затримку краще зменшувати без втрати контексту
(GPU або менша модель, коротші вікна для фрагментів з кодом, text+graph лише для питань про зв'язки).
