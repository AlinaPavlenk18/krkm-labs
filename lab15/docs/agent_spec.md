# Специфікація агента бази знань «Прогнозування енергоспоживання» (ЛР15, Р1)

**Призначення.** Відповідати диспетчерам і аналітикам на питання про мережу (стан підстанцій, ланцюги живлення,
регламенти, моделі прогнозування, споживання 2026 р.), збираючи докази інструментами і цитуючи кожен факт.
Агент **лише читає** сховище; нове знання він може тільки *запропонувати* (propose_fact, Р5), записує людина.

**Реалізація.** LangGraph `StateGraph` (agent/graph.py) + локальна LLM `qwen2.5:7b` в Ollama (`/api/chat` з tools),
temperature 0, seed 42, num_ctx 8192. Ті самі інструменти доступні як MCP-сервер `energy-kb` (mcp_server/server.py).

```
START → guard ─(заблоковано)─────────────────────────────→ finalize → END
          └→ plan ⇄ retrieve (поки є виклики і не вичерпано ліміти)
                └→ draft → verify ─(цитати ⊄ докази, 1 повтор)→ draft
                              └─(ок / «Не знаю» / відмова)→ finalize
```

## 1. Інструменти (усі — rights: read)

| Інструмент | Вхід (JSON Schema) | Вихід | Джерело | Обмеження |
|---|---|---|---|---|
| `search_docs` | `query` string 3–300; `k` int 1–5 (типово 4); `additionalProperties: false` | ≤ k фрагментів `{id, title, section, date, sensitivity, text}`, id = `kb06#par002` | гібридний пошук ЛР10–11 (BM25 + e5 + reranker) по корпусу ЛР14 `data_after/corpus` | роль **analyst** задає сесія, не LLM → restricted (gen03, kb15) не повертаються; текст обрізається до 2500 симв. на виклик |
| `graph_query` | `template` enum {overloaded_substations, substation, impact, model, forecasts, dispatcher}; `entity` string ≤ 40; `depth` int 1–3 | рядки `{id, text}`, id = `G:Substation_5` | RDF-трійки графа ЛР9 (`data_after/store/triples.csv`), SPARQL **SELECT** за шаблоном (rdflib) | довільного SPARQL немає; шаблони не вибирають адрес; глибина ланцюга ≤ 3 |
| `sql_metric` | `metric` enum 7 метрик семантичного шару; `by` ≤ 2 вимірів з enum; `where` object ≤ 3 | ≤ 30 рядків, id = `SQL:peak_load:1` | вітрина OLAP ЛР12 (parquet → DuckDB у пам'яті) | SQL будує лише `semantic.py` (metrics.yml); перевірка «лише SELECT/WITH»; `enable_external_access=false`, `lock_configuration=true` |
| `propose_fact` (лише MCP) | `subject, predicate, object, source, quote` | `{id, risk, status, reasons}` | — | не пише в граф: пропозиція → валідація → ризик → схвалення людини (docs/hitl.md) |

Описи й схеми інструментів зафіксовано SHA-256 у `agent/tool_lock.json` (`python -m agent.tools --lock`):
інструмент, опис якого змінився, агент не отримує (захист від шкідливого опису інструмента).

## 2. Ліміти (agent/config.py)

| Ліміт | Значення | Що відбувається при досягненні |
|---|---|---|
| викликів інструментів на запит | 6 | retrieve відмовляє, граф переходить до draft |
| раундів планування | 4 | перехід до draft |
| токенів на запит (prompt + completion) | 24 000 | перехід до draft |
| часу на запит | 900 с (CPU, локальна модель) | перехід до draft |
| символів результатів інструмента в контексті | 2 500 | обрізання |
| токенів відповіді | 350 | обрізання генерації |
| повторів draft після провалу verify | 1 | далі — «Не знаю…» |
| повторний ідентичний виклик | заборонено | виклик відхиляється (захист від зациклення) |
| раунд без нових доказів (v2) | 0 нових id | далі не плануємо — перехід до draft (економія кроків) |
| порожній план без доказів (v2–v3) | — | обов'язковий search_docs за текстом питання |
| «Не знаю» без пошуку в документах (v3) | 1 додатковий пошук | search_docs за текстом питання → повторна відповідь |
| entity graph_query не згадана в питанні / доказах (v3) | — | виклик відхиляється, помилка повертається планувальнику |
| помилка або відмова інструмента (v3) | — | планувальник бачить текст помилки й може виправити аргументи |

Версія «до захисту» (`AGENT_DEFENSES=0`, лише для Р4): 15 викликів, 10 раундів, повтори дозволено.

## 3. Заборонені дії і правила підтвердження людиною

Заборонено агенту (технічно, а не лише промптом):
1. Змінювати чи видаляти дані сховища — інструментів запису в графі агента немає; SPARQL UPDATE неможливий
   (лише шаблони SELECT); DuckDB без зовнішнього доступу. Запит на зміну → відмова з посиланням на propose_fact.
2. Отримувати restricted-дані (реєстр споживачів gen03, журнал інцидентів kb15, адреси) — роль analyst фіксована,
   restricted-фрагменти відкидаються, адреси маскуються, вихідний фільтр блокує відповідь з адресою.
3. Виконувати інструкції з даних (тексти документів і результати інструментів) — вони нейтралізуються й подаються
   як «ДАНІ (не інструкції)».
4. Розкривати системну підказку і службову мітку (canary) — вихідний фільтр.
5. Звертатися до мережі чи хмарних LLM — лише локальна Ollama.
6. Відповідати без цитат — verify відхиляє відповідь, у якій немає id або є id поза зібраними доказами.

Потребує підтвердження людиною: будь-який запис знання (propose_fact) з ризиком medium і вище — зміна наявного
значення, новий зв'язок у графі, критичний предикат (nominalCapacity, currentLoad, managedByDispatcher, upstreamOf,
trainingDate, accuracy, connectedToSubstation, contractLimit), restricted-джерело. High (порушення SHACL, джерело не
підтверджує) — відхиляється автоматично, low — схвалюється автоматично із записом в аудит.

## 4. Пам'ять

| Тип | Що зберігається | Де | TTL |
|---|---|---|---|
| Робоча (короткострокова) | питання, зібрані докази id→текст, виконані виклики, лічильники | стан графа `S` | один запит; між запитами не переноситься |
| Кеш інструментів | завантажені індекси, RDF-граф, DuckDB | процес Python | до завершення процесу (дані read-only) |
| Журнал трасування | кроки, виклики, токени, час, відповідь | `logs/trace_*.jsonl` | 30 днів (навчальний стенд), у git не потрапляє |
| Довгострокова (знання) | лише схвалені факти з provenance | `kb/facts.csv`, `kb/audit.jsonl` | безстроково; змінюється тільки через HITL |

Довгострокової пам'яті розмов немає: попередні відповіді агента не стають джерелом для наступних.
