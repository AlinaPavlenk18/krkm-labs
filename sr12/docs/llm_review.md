# Перевірка схеми, запропонованої LLM (СР12)

LLM: qwen2.5:7b (Ollama, локально), temperature 0, seed 42, підказка `prompts/schema_v1.md`,
сирий вихід — `llm_log/qwen_schema_raw.md` (612 / 867 токенів, 95,8 с). DDL LLM виконано скриптом
`scripts/check_llm_ddl.py`: 4 CREATE TABLE пройшли, 3 ALTER TABLE … FOREIGN KEY — ні
(DuckDB не підтримує додавання зовнішніх ключів через ALTER TABLE), тож у схемі 0 зовнішніх ключів.

## Три недоліки і виправлення

| № | Аспект | Що запропонувала LLM | Чому це помилка | Виправлення у фінальній схемі |
|---|---|---|---|---|
| 1 | Зерно | «Зерно» — перелік вмісту таблиці, а не визначення рядка; у рядку окремі стовпці `VARPrediction` і `LSTMPrediction` поряд із `ModelID`; горизонту немає | незрозуміло, що означає рядок: прогноз однієї моделі чи всіх одразу; прогнози на 1 і 7 діб на ту саму дату не розрізнити (питання 1); нова модель потребує нового стовпця | зерно «одна версія моделі × підстанція × цільова дата × горизонт»; один стовпець `forecast_kwh`; вимір `dim_horizon`; PK = (model_key, substation_key, target_date_key, horizon_key) |
| 2 | Ключі | `FactID` замість ключа зерна; природний `ModelID` без версій; `Version`, `TrainingDate`, назви й область — у факті; FK через ALTER TABLE (у DuckDB не створюються); SCD для версії — «нова замінює попередню» (тип 1) | дублікати зерна не відловлюються; при перезаписі версії втрачається історія, і питання 3 (до/після перенавчання) не має відповіді; без FK можливі «сироти» | сурогатний `model_key` версії у `dim_model` (SCD 2: version, training_date, valid_from/valid_to, is_current); версію беремо на **дату складання** (рольова `issue_date_key`); FK оголошено в CREATE TABLE; перевірка «сиріт» = 0 |
| 3 | Адитивність | WAPE — «адитивна, кВт·год», тип `VARBINARY`; споживання й похибка — `INTEGER`; похибки зі знаком і накопиченої похибки немає | WAPE — відношення у %, не сумується між підстанціями чи днями; бінарний тип не агрегується SQL; INTEGER обрізає дробові кВт·год; без похибки зі знаком немає зсуву (питання 4), без накопиченої — питання 5 | WAPE не зберігається, а рахується Σ\|e\| / Σ факт; адитивні `forecast_kwh`, `actual_kwh`, `error_kwh`, `abs_error_kwh` (DOUBLE); неадитивна `ape_pct`; напівадитивна `mtd_abs_error_kwh` |

Додатково: «Точність» і «Дата навчання» подано як окремі виміри, хоча це атрибути версії моделі; таксономії класів
моделей (питання 2) у схемі LLM немає. Зі схеми LLM на питання 1 можна відповісти лише без розділення горизонтів; на питання 2, 4 і 5 — ні; на питання 3 —
лише якщо не застосовувати запропоновану самою LLM політику «нова версія замінює попередню».
