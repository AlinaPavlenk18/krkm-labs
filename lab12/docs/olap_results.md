## q01_rollup_taxonomy

**Питання.** B1. Скільки енергії спожито за січень 2026 за класами таксономії (клас → підклас) і разом?

**Конструкція.** ROLLUP + GROUPING()

```sql
SELECT CASE WHEN GROUPING(k.parent_label) = 1 THEN 'УСЬОГО' ELSE k.parent_label END AS клас,
       CASE WHEN GROUPING(k.class_label) = 1 THEN '(разом)' ELSE k.class_label END AS підклас,
       replace(k.class_iri, 'http://www.semanticweb.org/energy-forecasting#', 'ef:') AS iri,
       round(sum(f.energy_kwh) / 1000, 2) AS енергія_мвт_год,
       round(100 * sum(f.energy_kwh) / (SELECT sum(energy_kwh) FROM fact_consumption), 1) AS частка_pct
FROM fact_consumption f JOIN dim_consumer_class k USING (class_key)
GROUP BY ROLLUP (k.parent_label, (k.class_label, k.class_iri))
ORDER BY GROUPING(k.parent_label), GROUPING(k.class_label), енергія_мвт_год DESC;
```

**Результат** (5 рядків):

| клас     | підклас              | iri                    |   енергія_мвт_год |   частка_pct |
|:---------|:---------------------|:-----------------------|------------------:|-------------:|
| Споживач | Промисловий споживач | ef:IndustrialConsumer  |           1483.93 |         77   |
| Споживач | Комерційний споживач | ef:CommercialConsumer  |            363.6  |         18.9 |
| Споживач | Побутовий споживач   | ef:ResidentialConsumer |             78.69 |          4.1 |
| Споживач | (разом)              | nan                    |           1926.23 |        100   |
| УСЬОГО   | (разом)              | nan                    |           1926.23 |        100   |

**Інтерпретація.** за січень спожито 1926,23 МВт·год; 77,0 % припадає на промислових споживачів (7 споживачів), 18,9 % — на комерційних, 4,1 % — на побутових (23 споживачі). Рядки ROLLUP із GROUPING() = 1 — підсумки за класом :Consumer і загальний; вони збігаються, бо корінь таксономії один.

## q02_drilldown_taxonomy

**Питання.** B1 (деталізація). Drill-down по таксономії: підклас ef:CommercialConsumer → окремі споживачі; хто дає найбільший внесок?

**Конструкція.** GROUPING SETS (підклас; підклас + споживач) — drill-down на рівень нижче

```sql
SELECT replace(k.class_iri, 'http://www.semanticweb.org/energy-forecasting#', 'ef:') AS iri,
       coalesce(c.consumer_id, '(разом за підкласом)') AS споживач,
       round(sum(f.energy_kwh) / 1000, 2) AS енергія_мвт_год,
       round(100 * sum(f.energy_kwh) / sum(sum(f.energy_kwh)) OVER (PARTITION BY GROUPING(c.consumer_id)), 1) AS частка_pct
FROM fact_consumption f
JOIN dim_consumer_class k USING (class_key)
JOIN dim_consumer c USING (consumer_key)
WHERE k.class_iri = 'http://www.semanticweb.org/energy-forecasting#CommercialConsumer'
GROUP BY GROUPING SETS ((k.class_iri), (k.class_iri, c.consumer_id))
ORDER BY GROUPING(c.consumer_id) DESC, енергія_мвт_год DESC;
```

## q03_cube_weekend

**Питання.** B6. Як відрізняється середнє добове споживання в будні й вихідні за класами (з усіма підсумками)?

**Конструкція.** CUBE (клас × тип дня) + GROUPING()

```sql
SELECT CASE WHEN GROUPING(k.class_label) = 1 THEN 'усі класи' ELSE k.class_label END AS клас,
       CASE WHEN GROUPING(d.is_weekend) = 1 THEN 'усі дні'
            WHEN d.is_weekend THEN 'вихідні' ELSE 'будні' END AS тип_дня,
       count(DISTINCT d.date_key) AS днів,
       round(sum(f.energy_kwh) / 1000, 2) AS енергія_мвт_год,
       round(sum(f.energy_kwh) / 1000 / count(DISTINCT d.date_key), 2) AS мвт_год_на_добу
FROM fact_consumption f
JOIN dim_consumer_class k USING (class_key)
JOIN dim_date d USING (date_key)
GROUP BY CUBE (k.class_label, d.is_weekend)
ORDER BY GROUPING(k.class_label), k.class_label, GROUPING(d.is_weekend), d.is_weekend;
```

**Результат** (12 рядків):

| клас                 | тип_дня   |   днів |   енергія_мвт_год |   мвт_год_на_добу |
|:---------------------|:----------|-------:|------------------:|------------------:|
| Комерційний споживач | будні     |     22 |            300.37 |             13.65 |
| Комерційний споживач | вихідні   |      9 |             63.23 |              7.03 |

## q04_slice_coldest_day

**Питання.** B3. Зріз за одним днем: як розподілялося споживання за частинами доби в найхолодніший день 11.01.2026 (−15,5 °C у Львові за графом ЛР9)?

**Конструкція.** SLICE (dim_date = 2026-01-11) + розподіл за частиною доби й класом

```sql
SELECT h.part_of_day AS частина_доби,
       round(sum(f.energy_kwh) FILTER (WHERE k.class_label = 'Побутовий споживач'), 1)   AS побутові_квт_год,
       round(sum(f.energy_kwh) FILTER (WHERE k.class_label = 'Комерційний споживач'), 1) AS комерційні_квт_год,
       round(sum(f.energy_kwh) FILTER (WHERE k.class_label = 'Промисловий споживач'), 1) AS промислові_квт_год,
       round(avg(f.temperature_c), 1) AS сер_темп_c
FROM fact_consumption f
JOIN dim_date d USING (date_key)
JOIN dim_hour h USING (hour_key)
JOIN dim_consumer_class k USING (class_key)
WHERE d.date = DATE '2026-01-11'
GROUP BY h.part_of_day
ORDER BY min(h.hour_key);
```

**Результат** (4 рядків):

| частина_доби   |   побутові_квт_год |   комерційні_квт_год |   промислові_квт_год |   сер_темп_c |
|:---------------|-------------------:|---------------------:|---------------------:|-------------:|
| ніч            |              333.4 |               1375.8 |               7392.2 |        -18.3 |
| ранок          |              888.2 |               2309.2 |               7133.4 |        -15.3 |
| день           |              709.7 |               3251   |               7274   |        -13   |
| вечір          |             1155.5 |               1338.5 |               7329.8 |        -16   |

**Інтерпретація.** у найхолодніший день (неділя) комерційні споживачі мають денний максимум (3251 кВт·год), побутові — вечірній (1155,5 кВт·год), промислові споживають рівно протягом доби (вихідний: одна зміна не працює). Найнижча температура — вночі (−18,3 °C).

## q05_dice

**Питання.** B2. Підкуб: скільки енергії побутові й комерційні споживачі Львівської та Волинської областей спожили в пікові години будніх днів?

**Конструкція.** DICE (область ∈ {Львівська, Волинська} × клас ∈ {побутовий, комерційний} × is_peak × будні)

```sql
SELECT s.region_name AS область, k.class_label AS клас,
       count(DISTINCT f.meter_id) AS лічильників,
       round(sum(f.energy_kwh), 1) AS пік_квт_год,
       round(sum(f.energy_kwh) / count(DISTINCT f.meter_id), 1) AS на_лічильник_квт_год
FROM fact_consumption f
JOIN dim_substation s USING (substation_key)
JOIN dim_consumer_class k USING (class_key)
JOIN dim_hour h USING (hour_key)
JOIN dim_date d USING (date_key)
WHERE s.region_name IN ('Львівська область', 'Волинська область')
  AND k.class_label IN ('Побутовий споживач', 'Комерційний споживач')
  AND h.is_peak AND NOT d.is_weekend
GROUP BY ALL
ORDER BY область, клас;
```

**Результат** (4 рядків):

| область           | клас                 |   лічильників |   пік_квт_год |   на_лічильник_квт_год |
|:------------------|:---------------------|--------------:|--------------:|-----------------------:|
| Волинська область | Комерційний споживач |             4 |       45838.9 |                11459.7 |
| Волинська область | Побутовий споживач   |             3 |        2885.3 |                  961.8 |
| Львівська область | Комерційний споживач |             5 |       44643.8 |                 8928.8 |
| Львівська область | Побутовий споживач   |             4 |        4339.7 |                 1084.9 |

**Інтерпретація.** у підкубі (2 області × 2 класи × пікові години × будні) комерційні лічильники Волинської області споживають у пік більше на лічильник (11 459,7 кВт·год), ніж львівські (8928,8), а побутові — навпаки (961,8 проти 1084,9). Основне пікове навантаження в обох областях створюють комерційні споживачі.

## q06_pivot_part_of_day

**Питання.** B2. Яка частка енергії кожного класу припадає на кожну частину доби (ніч / ранок / день / вечір)?

**Конструкція.** PIVOT (рядки — клас, стовпці — частина доби), значення — частка, %

```sql
WITH base AS (
    SELECT k.class_label AS клас, h.part_of_day,
           100 * f.energy_kwh / sum(f.energy_kwh) OVER (PARTITION BY k.class_label) AS pct
    FROM fact_consumption f
    JOIN dim_consumer_class k USING (class_key)
    JOIN dim_hour h USING (hour_key))
PIVOT base ON part_of_day IN ('ніч', 'ранок', 'день', 'вечір') USING round(sum(pct), 1)
ORDER BY клас;
```

**Результат** (3 рядків):

| клас                 |   ніч |   ранок |   день |   вечір |
|:---------------------|------:|--------:|-------:|--------:|
| Комерційний споживач |  11.2 |    31.6 |   41.8 |    15.4 |
| Побутовий споживач   |  11.3 |    28.9 |   21.3 |    38.4 |
| Промисловий споживач |  17   |    29.2 |   28.8 |    25   |

**Інтерпретація.** профілі класів відрізняються: побутові споживачі — 38,4 % енергії ввечері, комерційні — 41,8 % удень, промислові розподілені найрівніше (найбільша частка вночі — 17,0 % — через другу зміну й вихідні). Для прогнозу це означає різні добові профілі для кожного підкласу таксономії.

## q07_window_cumulative

**Питання.** B7. Яка динаміка добового споживання: накопичене споживання з початку місяця і ковзне середнє за 7 днів?

**Конструкція.** віконні функції SUM() OVER (накопичення) і AVG() OVER (ROWS 6 PRECEDING)

```sql
WITH daily AS (
    SELECT d.date, d.day_name, sum(f.energy_kwh) AS e, avg(f.temperature_c) AS t
    FROM fact_consumption f JOIN dim_date d USING (date_key)
    GROUP BY d.date, d.day_name)
SELECT date AS дата, day_name AS день,
       round(e / 1000, 2) AS мвт_год,
       round(sum(e) OVER (ORDER BY date) / 1000, 2) AS накопичено_мвт_год,
       round(avg(e) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) / 1000, 2) AS ковз_7д_мвт_год,
       round(t, 1) AS сер_темп_c
FROM daily
ORDER BY date;
```

## q08_window_rank_substation

**Питання.** B4. Яке пікове годинне навантаження кожної підстанції відносно номінальної потужності і яке її місце в області?

**Конструкція.** агрегування до (підстанція, година) + MAX + віконна RANK() OVER (PARTITION BY область)

```sql
WITH hourly AS (
    SELECT substation_key, date_key, hour_key, sum(energy_kwh) AS load_kw
    FROM fact_consumption GROUP BY ALL),
peak AS (
    SELECT substation_key, max(load_kw) AS peak_kw, avg(load_kw) AS avg_kw
    FROM hourly GROUP BY substation_key)
SELECT s.region_name AS область, s.substation_name AS підстанція,
       s.nominal_capacity_kw AS номінал_квт,
       round(p.peak_kw, 1) AS пік_квт,
       round(100 * p.peak_kw / s.nominal_capacity_kw, 1) AS завантаження_pct,
       round(p.avg_kw / p.peak_kw, 2) AS коеф_навантаження,
       RANK() OVER (PARTITION BY s.region_name ORDER BY p.peak_kw / s.nominal_capacity_kw DESC) AS ранг_в_області
FROM peak p JOIN dim_substation s USING (substation_key)
ORDER BY завантаження_pct DESC;
```

## q09_scd2_over_limit

**Питання.** B5. Хто зі споживачів перевищував договірний ліміт і скільки годин — окремо для кожної версії ліміту (SCD 2)?

**Конструкція.** з'єднання з версією виміру SCD 2 + агрегат із FILTER + віконний ранг для топ-списку

```sql
WITH hourly AS (   -- споживач із двома лічильниками: спершу сума за годину
    SELECT consumer_key, date_key, hour_key, sum(energy_kwh) AS load_kw
    FROM fact_consumption GROUP BY ALL),
per_version AS (
    SELECT c.consumer_id, k.class_label, c.valid_from, c.valid_to, c.contract_limit_kw,
           count(*) FILTER (WHERE h.load_kw > c.contract_limit_kw) AS over_h,
           max(h.load_kw) AS max_kw
    FROM hourly h
    JOIN dim_consumer c USING (consumer_key)
    JOIN dim_consumer_class k USING (class_key)
    GROUP BY ALL)
SELECT consumer_id AS споживач, class_label AS клас, valid_from AS діє_з, valid_to AS діє_до,
       contract_limit_kw AS ліміт_квт, over_h AS годин_перевищення, round(max_kw, 1) AS макс_квт
FROM per_version
WHERE consumer_id = 'Consumer_3310'
   OR consumer_id IN (SELECT consumer_id FROM per_version WHERE consumer_id <> 'Consumer_3310'
                      ORDER BY over_h DESC, consumer_id LIMIT 5)
ORDER BY consumer_id = 'Consumer_3310' DESC, over_h DESC, consumer_id;
```

## q10_temperature_corr

**Питання.** B3. Наскільки добове споживання одного лічильника кожного класу залежить від температури (кореляція і нахил регресії)?

**Конструкція.** статистичні агрегати CORR() і REGR_SLOPE() над добовим зрізом

```sql
WITH daily AS (
    SELECT k.class_label AS клас, d.date, d.is_weekend,
           sum(f.energy_kwh) / count(DISTINCT f.meter_id) AS e, avg(f.temperature_c) AS t
    FROM fact_consumption f
    JOIN dim_consumer_class k USING (class_key)
    JOIN dim_date d USING (date_key)
    GROUP BY ALL)
SELECT клас,
       round(corr(e, t), 3) AS кореляція_всі_дні,
       round(corr(e, t) FILTER (WHERE NOT is_weekend), 3) AS кореляція_будні,
       round(regr_slope(e, t) FILTER (WHERE NOT is_weekend), 1) AS квт_год_на_1c_на_лічильник
FROM daily
GROUP BY клас
ORDER BY клас;
```

**Результат** (3 рядків):

| клас                 |   кореляція_всі_дні |   кореляція_будні |   квт_год_на_1c_на_лічильник |
|:---------------------|--------------------:|------------------:|-----------------------------:|
| Комерційний споживач |               0.184 |            -0.771 |                        -14.2 |
| Побутовий споживач   |              -0.932 |            -0.958 |                         -2.1 |
| Промисловий споживач |               0.25  |            -0.702 |                        -21.8 |

**Інтерпретація.** у будні споживання лічильника сильно залежить від температури: кореляція −0,958 для побутових, −0,771 для комерційних, −0,702 для промислових; кожен градус похолодання додає ≈ 2,1 / 14,2 / 21,8 кВт·год на добу на лічильник. Без розділення будні/вихідні кореляція для комерційних і промислових хибно додатна (0,184 і 0,250) — змішуються два режими роботи.
